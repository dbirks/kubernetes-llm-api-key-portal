How it works

{{.Brand.Name}} is a private, self-hosted LLM endpoint. It runs open-weight models on a single GPU in a homelab and exposes them over the same OpenAI- and Anthropic-compatible APIs your tools already speak — so you point a coding agent at it with an API key, and everything else works the way it always has.

{{/* The service at a glance. Spec chips carry the shape; the sentence carries the nuance a coworker needs before they wire a tool up to it. */}}
  • Single GPU · RTX PRO 6000 Blackwell · 96 GB
  • OpenAI & Anthropic compatible
  • Per-user API keys · Entra sign-in
  • Open weights · NVFP4 4-bit

Because it is one GPU rather than a fleet, models load on demand and unload when idle. The first request to a cold model waits a minute or two while it spins up; every request after that is warm until it goes idle again. Send the occasional retry that timing kindness, and it repays you with a fast, private endpoint you don't share with the rest of the internet. Nothing you prompt is stored by this portal.

Two things happen here, and only one of them involves this portal. Your prompts never pass through it.

What it's built on

  1. Your request An OpenAI- or Anthropic-shaped HTTPS call carrying your API key as a bearer token.
  2. Cloudflare + kgateway The public edge. Cloudflare Tunnel brings the request in; kgateway checks the key against its Kubernetes Secret and fails closed if it doesn't match.
  3. Envoy AI Gateway Routes by the model you named to the engine serving it, and shapes traffic across the co-resident models.
  4. KServe + llm-d Each model is an LLMInferenceService. It loads on the first request and scales back to zero when idle, which is what the cold start pays for.
  5. vLLM The inference engine that actually runs each model and streams tokens back to you.
  6. NVFP4 weights Models are quantised to 4-bit (W4A4) NVFP4, so they compute natively on the card's Blackwell FP4 tensor cores and several fit in one GPU at once.
  7. RTX PRO 6000 Blackwell One 96 GB GPU, shared across the resident models by HAMi. The whole service is this single card in a homelab — no cloud, no fleet.

The model catalog

{{if .Models}}See what's live →{{end}}

The catalog is growing toward roughly half a dozen models — a mix aimed at coding, reasoning, and general-purpose work. Each is addressed by name in the model field and served under its own base path: coding models on /v1, a reasoning model such as Muse-Glimmer on /muse/v1, and so on. One key reaches all of them; the base URL and the model name are what change between them. The {{if .Models}}models page{{else}}models page{{end}} shows which are published and warm right now, and your account page generates the exact copy-paste setup for each.

Worth knowing

  • Revoking deletes the Secret, so the key stops at kgateway.
  • The same key works for every supported client and every model.
  • Each model has its own base URL — Qwen on /v1, Muse-Glimmer on /muse/v1; set the model field to match. Your account page generates the exact snippet per model.
  • Nothing you prompt is stored by this portal.
