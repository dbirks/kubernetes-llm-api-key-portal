How it works

Two things happen here, and only one of them involves this portal. Your prompts never pass through it.

{{/* The connectors are decorative: every node carries its own text, so the diagram reads correctly with animation off, with CSS off, and to a screen reader. The two lanes run at different tempos on purpose — getting a key happens once, using it happens on every request. */}}

Getting a key

once
You, in a browser {{.Brand.ShortName}}
sign in
Microsoft Entra ID your work account
create key
This portal shows the key once
the portal writes one immutable Secret
Kubernetes Secret one per key · immutable
kgateway matches your key against it

Using the key

every request
Your coding agent Bearer <key> · model: …
/v1/* public endpoint
kgateway checks the key
Envoy AI Gateway routes by model name
KServe / llm-d loads on demand, runs it

Models scale to zero when idle, so the first request to a cold model waits while it loads; later requests are warm. See the model list.

Endpoints your key opens

GET/v1/models

POST/v1/chat/completions

POST/v1/responses

POST/v1/messages

Worth knowing

  • Revoking deletes the Secret, so the key stops at kgateway.
  • The same key works for every supported client and every model.
  • Choose a model with the model field; the gateway routes by that name.
  • Nothing you prompt is stored by this portal.
