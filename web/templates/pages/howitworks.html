How it works

A private, self-hosted LLM endpoint. It runs open-weight models on a homelab GPU and speaks the same OpenAI- and Anthropic-compatible APIs your tools already use, so you point Claude Code, Cursor, or any client at it with one API key and change nothing else.

Two things happen here, and only one of them involves this portal — your prompts never pass through it.

Kubernetes Secret one per key

The portal writes a Kubernetes Secret — one per key — and shows the raw value once. From then on it's out of the request path: Envoy AI Gateway checks each request's key against that Secret. Revoking deletes it, and anything using the key stops.

One gateway, both jobs

Envoy AI Gateway does both jobs: it authenticates the request — matching your key against its Secret — and then routes by model name to the right engine.

One key, every model

The same key reaches every model. Only the base URL and the model name change between them — the {{if .Models}}models page{{else}}models page{{end}} is the source of truth for which exist and where.

First request may wait

Models scale to zero when idle. The first request to a cold model can take a couple of minutes to load — or need a retry — then it's warm.
